PADRÃO GERAL ENCONTRADO
-----------------------------------------------------------------
Os 27 achados são qualitativamente reais — nenhum foi classificado
como NÃO CONFIRMADO ou INCORRETO. Mas o relatório original tem um
padrão sistemático de números "prova" imprecisos, e o repositório
está em movimento (hardening de segurança não commitado em
andamento). Os pontos mais importantes a ter em mente:

1. EVIDÊNCIA CITADA ERRADA: DB-03 cita billings.py:322 como exemplo
   de db.get() sem checar is_deleted — mas essa linha JÁ CHECA
   is_deleted no código atual. A tese do achado continua válida (há
   casos reais em outros arquivos), mas o exemplo dado está incorreto
   e a severidade foi rebaixada de Alta para Média por causa disso.

2. CONTAGENS INFLADAS: DB-02 diz 96 ForeignKeys (real: 45); DB-03 diz
   118 ocorrências de db.get() (real: 98, ~75-80% já protegidas);
   FE-05 diz 39 ocorrências (real: 30); FE-03 diz 143 tipos (real:
   117-155, dependendo do escopo contado).

3. COMPARAÇÃO TÉCNICA EQUIVOCADA: BE-04 compara _log_call com
   _run_locked em main.py, mas este último resolve um bug OPOSTO
   (commit descartado, não prematuro) — a analogia não se sustenta e
   deve ser descartada, embora o achado em si permaneça válido.

4. SCRIPT CITADO POR ENGANO: INT-03 cita ailos_homologacao.py como
   prova de padrão replicável para CNAB/Multiportal, mas esse script
   testa a API de boletos Ailos — uma integração diferente. Não fecha
   a lacuna real de CNAB.

5. DB-01 JÁ ESTÁ EM ANDAMENTO: existe backend/alembic/ com migração
   baseline (não commitada) e main.py já documenta ensure_schema_
   updates() como "histórico e congelado". Falta só automatizar
   `alembic upgrade head` no deploy — a decisão já foi tomada, só
   falta terminar a execução.

6. SEC-04 TEM RISCO REAL MENOR QUE O DESCRITO: o frontend
   (/login/cliente, /cliente/dashboard, /cadastro/cliente) já foi
   reduzido a stubs que redirecionam — não há mais UI órfã apontando
   para o portal do cliente morto. O risco é de reativação futura sem
   revisão, não de exposição hoje.

7. ACHADOS ADICIONAIS ENCONTRADOS QUE O RELATÓRIO NÃO CAPTUROU:
   - BE-02: 7 dos 15 endpoints de listagem nem têm skip/offset — não
     é só "sem total", é "sem página 2" (severidade sobe).
   - BE-06: existe um segundo arquivo (ailos_boletos.py) que já lê
     settings corretamente — a divergência entre os dois é um risco
     real de boleto com convênio errado, não só duplicação estética
     (severidade sobe).
   - INT-01: o rate limiter (SEC-03) é o consumidor óbvio do Redis
     ocioso — os dois achados têm o mesmo fix.
   - FE-04: Sidebar() nem recebe prop de usuário — não é filtro que
     falha, é informação que nunca chega ao componente.
   - SEC-05: o mesmo padrão de "logout total" também existe no catch
     de erro 401/403 genérico de qualquer chamada de API, não só no
     clique de menu errado.
